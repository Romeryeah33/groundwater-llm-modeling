### 2026-10-12 · 修：启动脚本被中文注释带崩（你报告的"双击没反应"）

**提交**：`0f4d234` / 标签 `v0.4.5`

**问题**：双击 `启动程序.bat` 起不来。**根因不是程序坏了，是 `.bat` 里的中文。**

cmd.exe 读 `.bat` 用的是**系统默认编码**（中文 Windows 上是 GBK），不是 UTF-8。某些中文字节序列会让解析错位，而且**整份文件一起遭殃** —— 症状看着毫无道理（例如把 `flopy` 报成 `lopy`）。另有第二条：`.bat` 必须是 **CRLF** 换行，LF-only 会让 `for ... do (...)` 块和 `goto :label` 失效。

**改动**：

| 文件 | 改了什么 |
|---|---|
| `scripts/launch.bat`（新，纯 ASCII） | 承接**全部**启动逻辑 |
| `启动程序.bat` | 只剩一行 `call scripts\launch.bat`（保留中文名，方便双击） |
| `启动程序-调试模式.bat` | 设 `GW_SHOW_DEBUG_PANELS=1` 后 `call scripts\launch.bat` |
| `.gitattributes`（新） | `*.bat text eol=crlf`；另给 png/pdf/docx/xlsx/shp 等标 binary |
| `tests/test_launchers.py`（新，9 项） | 锁住编码与换行两条规则 |

**为什么这么改**：两条可选解 —— 全部 ASCII，或在第一个中文字节**之前**先 `chcp 65001`。此处选**全部 ASCII**（更稳，不依赖 cmd 的 `chcp` 行为）。中文名脚本无法避免（要给人双击），所以让它们**只做入口、不含逻辑** —— 并且实测**批处理不能 `call` 一个中文名的批处理**，逻辑留在中文名文件里必踩。

**验证**：`tests/test_launchers.py` 9/9。两条规则都做了变异自检：把中文挪到 `chcp` 之前 → 红；把 `.gitattributes` 那行删掉 → 红。过程中修掉自己写出的两处**假绿** —— 规则 1 原先用朴素子串找 `chcp 65001`，结果匹配到了**解释用的英文注释**（改成匹配行首的整行命令）；规则 3 原先用 `errors="replace"` 解码，中文全变 U+FFFD，正则永远不可能命中（改成直接在字节层扫）。

**影响**：双击恢复正常。`eol=crlf` 让**任何平台**检出都写 CRLF，所以这个坑不会再回来。

### 2026-10-12 · 阶段 B：最小 REST 接口真的通了

**提交**：`832e9b4` / 标签 `v0.4.4`

**问题**：`app/api/routes.py` 里那四个函数**全是 TODO 占位**，而且**全仓没有一处 `include_router`** —— README / CLAUDE.md 承诺的 API **从来没有生效过一天**。

**改动**：

| 文件 | 改了什么 |
|---|---|

| `app/api/routes.py` | 四个主干端点 + 一个结果文件下载端点；`_POOL = ThreadPoolExecutor(max_workers=1)`、`_TASK_LOCK` |
| `app/main.py:93` | 补 `app.include_router(routes.router)`；新增统一入口 `python -m app.main`（一个进程同时提供网页 7860 与接口 8000） |
| `app/llm_agent/llm_client.py:61-64` | 补上请求超时（`settings.llm_request_timeout` 定义了却**从没传给 litellm**） |
| `app/llm_agent/session_registry.py` | 消毒函数收进注册表内部，界面与接口共用**同一张**会话表 |
| `README.md` / `CLAUDE.md` / `.env.example` | 补端点用法、统一入口、新环境变量 |

**为什么这么改**：

- **跑模型做成"后台线程 + 轮询"而不是同步返回**：`build_and_run` 里 mf6 子进程 timeout 是 3600 s，而 nginx 读超时 600 s —— 同步阻塞的话，一次长算会被反代掐断，客户端什么也拿不到。
- **工作线程数刻意设为 1**：`plot_styler` / `_result_cache` 是**进程级单例**，同时跑两个模型会互相串图。（界面与接口**同时**跑仍有风险，见已知限制。）
- **必须抽 `run_gates`**：三道闸原先只长在界面里，`scripts/run_case.py` 又抄了一遍，接口是第三个调用方；三处各写一遍必然漂移，而漂移的表现是"界面拦下的用例接口照样能跑"—— 不报错、不崩，只是结果对不上，最难查。
- **不引 Celery / Redis**：需求是"最小一组"，而单进程单线程池本来就只能跑一个任务，加外部队列解决不了任何现有问题。

**验证**：

- `tests/test_api_endpoints.py`（新，21 项）：端点注册、sid 校验、任务生命周期、文件白名单、密钥不外泄、`API_TOKEN` 门禁、超时确实传下去了。
- **不许漂移（本阶段最重要的一条）**：同一个 IR 分别走界面与接口，拦下 `AutoModelBuilder.build_and_run` 比对入参 —— 两份 IR **逐字节相同**（含物化后的源区 `grid_indices`）。变异：给接口侧塞一个"偷懒版"闸门 → 两份立刻不同 → 断言确实会红。
- **实跑 HTTP**（不只是 `TestClient`）：提交 → 轮询 28 s → `completed`，摘要含 `water_balance_error` 等 8 项，下载 10 MB 的 `.ucn` 成功。统一入口实测两个端口同时 200、`/docs` 可用。
- **过程中修掉一个真坑**：结果文件是分目录放的（`auto_model/auto_model_gwt.ucn`），而下载路由原先写 `{name}` —— 普通路径参数不匹配斜杠，带子目录的文件根本下不下来。已改成 `{name:path}`，并补了"嵌套路径"这条测试（原先只测顶层文件，所以漏了）。

**影响**：README 承诺的接口**现在是真的**。接口只返回结构化摘要与文件路径，**不返回可交互的模型对象**（那些对象在内存里、跨不了进程）—— 这是有意的功能边界。另：`/api/chat` 补超时后，失败行为从"无限等待"变成"超时报错"。

**为什么这么改**：

- **反应写在 `MST6`，不是 `IST6`。** 计划原文写的是「`ModflowGwtist` 接入」，**方向是错的**。
  MF6 的 **IST6 是 "Immobile Storage and Transfer" —— 双域（mobile–immobile）包**。
  按计划建 `ModflowGwtist` 后，MF6 6.3.0 直接硬报
  `DUAL DOMAIN IS ACTIVE BUT ZETAIM WAS NOT SPECIFIED`，必须再补 `THETAIM`/`ZETAIM`
  两个**假想的非移动域参数**才能跑 —— 那就把单域模型悄悄改成了双域模型。
  把 IST6 的 dfn 定义与 `ModflowGwtmst.__init__` 的签名对照后确认：**反应（吸附 + 降解）属于 MST6**，
  而项目**本来就构建了 MST6**（只是调用时没传反应参数）。
- **`half_life` 这条路径从来没有接线。** IR schema、校验器、提示词都提到了半衰期，
  但 `map_transport_params` 只读 `first_order_rate` —— 用户给半衰期等于什么都没给。
  现已按 λ = ln2/t½ 换算（放在程序里做，不交给 LLM：LLM 换算既不透明也无从核对）。
- **`first_order_rate` / `half_life` 不在 `PHYSICAL_RANGES` 里。** `check_param` 落到
  「不在已知物理范围表中，默认通过」的 INFO 分支 —— **看起来查过了，一个值都没查**，
  与板块一 porosity 逐层那次是同一类空转。现已补上范围条目（t½ 的上下界就是 λ 的倒数）。
- **单位陷阱（1000 倍）**：IR 惯用 Kd = L/kg、ρb = kg/L；MF6 的 `DISTCOEF` 要 **m³/kg**、
  `BULK_DENSITY` 要 **kg/m³**。这两个单位在数值上互为倒数（乘积无量纲），
  所以**直接填文献值，阻滞因子 R 看着是对的，但吸附相浓度会差 1000 倍**。
  转换常量：`_KD_L_PER_KG_TO_M3_PER_KG = 1e-3`、`_RHOB_KG_PER_L_TO_KG_PER_M3 = 1e3`。
- **吸附与降解同时启用时必须给 `DECAY_SORBED`**，否则 MF6 硬报
  `DECAY_SORBED not provided in GRIDDATA block but decay and sorption are active.`。
  **取 0 是有依据的**：令 λ_sorbed = 0 时总方程恰好退化为经典（与 MT3DMS 同源）形式
  `R·∂C/∂t = ∇·(D∇C) − v·∂C/∂x − λC`；若取 λ_sorbed = λ，等效衰减率会变成 λR，与解析解对不上。
  同时给一条提示，让用户知道这个值不是我们瞎填的。
- **说了要反应却给不出参数时必须说出来**：「启用吸附但没给 Kd」「启用降解但 λ/t½ 都没有」
  不静默按无反应建包，而是留下可展示的警告。
