# 新手指南 —— 怎么把这个系统用起来

> 这份文档写给**使用者**：你拿到这套程序，想用它建一个地下水模型。
> 不需要看懂代码，照着做即可。程序本身的开发记录在别的文档里，这里不涉及。

---

## 一、它是干什么的

你用**中文**描述想建的模型（区域范围、网格、含水层参数、边界条件、污染物……），
它调用大语言模型把你的话解析成参数，**再用物理规律校验一遍**，然后自动生成并运行
MODFLOW 6 模型，最后给出水头场、污染羽、过程分析图和一份报告。

一句话：**你用说话的方式建模，它负责翻译成模型、跑起来、给你看图。**

---

## 二、第一次使用：装一次就好

### 1. 确认有 Python

需要 **Python 3.11 或更高**。打开命令行输入：

```bash
python --version
```

显示 `Python 3.11.x` 或更高即可。没有的话去 <https://www.python.org/downloads/> 装一个，
安装时**记得勾选 "Add Python to PATH"**。

### 2. 装依赖

在项目文件夹里打开命令行，执行：

```bash
pip install -r requirements.txt
```

这一步会下载 gradio、flopy 等库，几分钟。**只需做一次。**

### 3. 配置一个密钥文件

```bash
cp .env.example .env
```

然后编辑 `.env`，把 `LLM_API_KEY=` 后面改成你自己的密钥。

> **也可以跳过这步** —— 启动后在网页上填也行（见第四节）。只是填了 `.env`
> 的话，自己用起来不用每次再填。

---

## 三、启动

### 最省事的办法：双击

在项目文件夹里**双击 `启动程序.bat`**。

会弹出一个小窗口显示启动进度，第一次启动可能要等 **1～2 分钟**（要初始化
大语言模型组件）。等它显示"Server is ready"并自动打开浏览器，就可以用了。

**用完之后**：关掉那个黑色小窗口即可。不要用别的方式关浏览器就算完——
服务还在后台跑着。

### 遇到问题想看看日志

**双击 `启动程序-调试模式.bat`**，界面会多出两个平时藏着的面板：
左侧的「流水线追踪」和结果区的「图件修改」页签。**排查自己的问题时才用它**，
平时不用（原因见第七节）。

### 命令行启动（如果你习惯命令行）

```bash
python -m app.main
```

- 网页界面：<http://127.0.0.1:7860>
- 接口文档：<http://127.0.0.1:8000/docs>

## 四、填你自己的 LLM 密钥（重要）

**每个使用者填自己的密钥** —— 不共用、也不烧别人的额度。

1. 打开网页后，看**左侧栏**，找到 **「模型密钥设置（可选）」** 这个**折叠面板**，点开它。
   （默认是收起的，以免吓到只想直接上手的人。）
2. 面板里有三个框：
   - **「LLM API Key」** —— 把密钥粘进去（密码框，输入时显示成圆点）。
   - **「模型」** —— 你已经预填了服务器配置里的模型名，按需改。
   - **「API Base」** —— 服务商的接口地址。
3. 常用服务商填法：

   | 服务商 | 模型 | API Base |
   | --- | --- | --- |
   | DeepSeek | `deepseek-chat` | `https://api.deepseek.com/v1` |
   | OpenAI | `gpt-4o` | `https://api.openai.com/v1` |
   | 通义千问 | `qwen-plus` | `https://dashscope.aliyuncs.com/compatible-mode/v1` |

4. 点 **「应用密钥」**，下面会显示成功或失败。
   **要点这个按钮才生效** —— 粘完不等它，直接去对话用的是旧密钥。

几点说明：

- **留空就用服务器已经配好的那把密钥**（`启动程序.bat` 的 `.env` 里那份）——
  自己一个人用、或者懒得每次填，就这样也行。
- 密钥**只存在服务器内存里**，不会写进任何文件、也不会进日志。
  **重启程序后就没了**，要重新填（或干脆写进 `.env`）。
- 界面上不会显示你的密钥明文。
- **每个人用自己的浏览器打开，就是独立的会话** —— 你填的密钥、你建的参数、
  你的对话，别人看不到，也不会互相覆盖。刷新页面会话还在。

## 五、界面怎么用

大体是「左侧说需求 → 中间看参数 → 右侧看结果」：

1. **左侧输入**：用中文说你要建什么。例如
   *"建一个单层模型，1000 米 × 800 米，分 50 行 40 列，渗透系数 15 米每天，
   西边界定水头 100 米"*。
   也**可以直接上传** SHP 等文件。
2. 它会**先检查参数够不够**。如果缺关键参数，会**拦住你并列出缺什么**，
   照着补上再继续 —— 这一步是故意的，缺参数建出来的模型没有意义。
3. 参数齐了会**再做一遍物理校验**（数值在不在合理范围、单位对不对）。
4. 点**运行**，等模型跑完（几十秒到几十分钟，取决于规模）。
5. **右侧看结果**：水头场、污染羽、过程贡献分析等图，以及可下载的报告。

## 六、用接口（给会写程序的同事）

除了网页，还有一套 REST 接口。接口文档会自动生成，浏览器打开
<http://127.0.0.1:8000/docs> 就能看到并直接试。

> 要**写成程序去调**它，请看 [`api_reference.md`](api_reference.md) ——
> 那份把每个字段、每种错误码都写全了。下面只给个能跑起来的最短路径。

一共五条（前四条是主干，最后一条负责下载文件）：

| 接口 | 作用 |
| --- | --- |
| `POST /api/chat` | 发一句话，拿回解析结果 |
| `POST /api/model/run` | 提交建模任务，立刻返回一个 `task_id` |
| `GET /api/model/status/{task_id}` | 查进度：`queued` / `running` / `completed` / `failed` |
| `GET /api/model/result/{task_id}` | 拿结果摘要与文件路径 |
| `GET /api/model/result/{task_id}/files/{文件路径}` | 下载结果图/报告 |

命令行里试一下：

```bash
# 1) 对话（密钥走请求头，不要放进 body）
curl -X POST http://127.0.0.1:8000/api/chat \
  -H "Content-Type: application/json" \
  -H "X-LLM-API-Key: sk-你的密钥" \
  -d '{"message":"单层网格 100x100x1，纵向弥散度 20 m","session_id":"me-001"}'

# 2) 提交建模（参数用上一步得到的 json_ir）
curl -X POST http://127.0.0.1:8000/api/model/run \
  -H "Content-Type: application/json" \
  -d '{"json_ir":{...},"session_id":"me-001"}'
# → {"task_id":"...","status":"queued"}

# 3) 轮询进度，看到 completed 再取结果
curl http://127.0.0.1:8000/api/model/status/<task_id>
curl http://127.0.0.1:8000/api/model/result/<task_id>

# 4) 下载某个结果文件（文件名要用 /result 里给出的 files[].path，别自己拼）
curl -O -J http://127.0.0.1:8000/api/model/result/<task_id>/files/auto_model/auto_model_gwt.ucn
```

要注意的：

- **接口这条路只跑模型，不生成图、不生成报告。** 它给你的是一份数据摘要
  （水头范围、水均衡等）和模型输出文件。**要看图、要下载 Word 报告，
  只能用网页界面** —— 同一个模型，界面上跑一遍就有了。
- **提交不等待** —— `/api/model/run` 立刻返回，模型在后台跑，你得轮询 `/status`。
  一次长算可能几十分钟，这是正常的。
- **`session_id` 只能用英文、数字、下划线、短横线**，其他字符会被直接拒绝
  （不会替你改写，因为那会造成两个不同的编号撞成同一个）。
- 接口**不返回可交互的模型对象**，只给结构化的摘要和文件路径 —— 那些对象是内存里的，
  跨不了进程。

## 七、已知限制（用之前先知道）

1. **同一时间只让一个人跑模型。** 跑模型很吃内存，而且结果图的内部状态是全局共享的。
   多个人同时跑，图和日志可能互相串。**排队用，或者错开时间。**

2. **接口不返回模型对象。** 需要模型对象的话请用网页端。

3. **平时看不到「流水线追踪」和「图件修改」两个面板，这是有意的。**
   它们挂在全局共享的状态上，多人同时用会**看到彼此的日志和设置**。所以默认对使用者
   隐藏，只在 `启动程序-调试模式.bat` 里打开（那是给你自己排查问题用的）。

4. **`.env` 里的密钥是"兜底"用的。** 你在网页上填的密钥优先；没填时才用 `.env` 里那份。
   如果是多人共用的服务器，**不要**把某人的密钥写进 `.env`。

5. **这套程序目前是"本机跑通"的状态。** 部署到服务器上还需要额外处理一些事情
   （端口、容器、密钥不进镜像等），那些没在本文档范围内 —— 参见
   `docs/后续开发计划20261010.md` 的「部署待办」一节。

## 八、常见问题

**问：双击 `启动程序.bat` 之后窗口一闪就没了，或者提示找不到 Python。**
答：多半是 Python 没装好或没勾 "Add Python to PATH"。命令行执行
`python --version` 确认；不行就重装 Python 并勾上那个选项。

**问：提示端口被占用（7860 或 8000）。**
答：说明已经有一个实例在跑。关掉之前的黑色窗口再启动，或换个端口
（`.env` 里改 `GRADIO_PORT` / `GW_API_PORT`）。

**问：点了"应用密钥"报错说密钥无效。**
答：检查密钥有没有复制全（前后别带空格）、模型名和 API 地址是否和服务商匹配
（见第四节的三组示例）。

**问：模型跑很久没动静，是死了吗？**
答：不一定。网格大、时间步多的时候跑几十分钟很正常。**不要重复点运行**，
重复提交会让多个任务抢同一份资源。

**问：我关掉浏览器，下次打开参数还在吗？**
答：**在**（会话编号存在浏览器里）。但如果是**另一台电脑或另一个浏览器**，
就是另一个独立会话，看不到之前的。

**问：模型跑出来结果不对。**
答：先在界面上回头核对**参数摘要**那一栏（它会显示实际写进模型的值与来源）。
如果参数和你说的不一致，多半是描述里信息不够或有歧义，补清楚再说一遍。
